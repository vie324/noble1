# ノーブル業務システム 追加開発のご提案

作成日：2026-05-29
対象：ノーブル経営ダッシュボード 追加開発

---

## 1. 本提案の目的

現在ご利用中の経営ダッシュボードを、単なる売上分析ツールから「ノーブルの業務はこのシステムを見れば分かる」という**業務集約プラットフォーム**へ発展させます。

特に今回は、現在ご利用中の **KaruteKun（カルテ）** と **TimeTree（シフト・店舗予定）** の役割を、新システムへ段階的に乗せ替えることを最優先とします。

---

## 2. 全体方針

### 2.1 「分析ツール」から「業務基盤」へ

これまでのダッシュボードは、売上などの**結果を入力して分析する**仕組みでした。
今回の追加開発では、**現場の日々の入力（カルテ）を起点に、分析・回数券残高・申し送りが自動でつながる**構造に作り替えます。

```
　　　　　　【今まで】　　　　　　　　　　　　　　【これから】

　売上を手入力 → 分析　　　　　　　　カルテ入力 ─┬→ 売上・部位別分析（自動）
　　　　　　　　　　　　　　　　　　　　　　　　　├→ 回数券の消化・残高（自動）
　カルテは KaruteKun　　　　　　　　　　　　　　　├→ 申し送り・LINE導線
　シフトは TimeTree　　　　　　　　　　　　　　　　└→ 同意書・在庫 …
```

### 2.2 中核は「顧客・カルテ・回数券」

すべての機能は **顧客** を中心に、**来店記録（カルテ）** と **回数券** という背骨にぶら下げます。
この3つを最初に正しく作ることで、後から追加する機能（申し送り・シフト・在庫・分析）が自然につながります。

### 2.3 段階的リリース

一度に全部を作るのではなく、現場が**1機能ずつ実際に移行できる単位**でリリースします。
最初のゴールは「**KaruteKun を新システムに置き換えられる状態**」です。

## 3. 技術構成のご提案

| 項目 | 採用技術 | 理由 |
|---|---|---|
| アプリ基盤 | **Next.js**（Vercel） | iPad/スマホで快適。ホーム画面に追加して**アプリのように**使える（PWA） |
| データベース | **Supabase（PostgreSQL）** | 回数券の金額・残回数を**正確に**管理。返金・トラブル対応に耐える |
| 認証・権限 | **Supabase Auth + RLS** | 管理者／スタッフの権限分離、店舗ごとのアクセス制御 |
| ファイル保存 | **Supabase Storage** | 施術前後の写真・同意書PDFを安全に保存 |
| リアルタイム | **Supabase Realtime** | 共有カレンダー・出勤状況を即時反映 |
| 連携・自動処理 | Edge / Serverless Functions | LINE連携、PDF生成、将来のAIシフト案 |

> ご想定どおり **Vercel + Supabase** は本要件に最適です。個人情報・施術写真・前受金（回数券）を扱うため、データベースは**Tokyoリージョン**で構築します。

### アカウント方針

開発スピードを優先し、**まず坂井さんアカウントで構築**します。
ただし本システムは顧客の個人情報・施術記録・同意書・前受金データを保持するため、**本番運用に移行する段階でノーブル様所有のアカウント（Organization）へ移管**できる前提で設計します。データの所有・引き継ぎで後々もめないための措置です。

## 4. 開発フェーズと優先順位

クライアント様のご要望の優先順位に沿って構成しています。

### Phase 0：基盤構築
認証・権限（管理者／店長／スタッフ）・店舗・中核データ（顧客／カルテ／回数券）の土台。既存スプレッドシートからのデータ移行。

### Phase 1：KaruteKun 代替【最優先・MVP】
- iPadで使いやすいカルテ画面
- 全店舗合算／店舗別の切り替え
- 「今日」の来店一覧
- **来店前に空のカルテ（箱）を一括作成**
- **未記入カルテが一目で分かる表示**（記入漏れ防止）
- 施術メニュー・**施術部位**・回数券利用状況の記録
- 施術前後写真の登録／自由記述メモ／重要事項の強調表示
- 顧客ごとの過去カルテ履歴

→ **これ単体で KaruteKun を置き換えられる状態**が最初のゴールです。

### Phase 2：回数券管理 × カルテ連動
- 顧客ごとの保有回数券（購入日・有効期限・購入回数・残回数）
- カルテ入力からの回数券消化
- 未消化回数・未消化金額、ダッシュボード残高と連動
- 有効期限が近い顧客のアラート

### Phase 3：顧客対応の一元管理
- 申し送り・要注意フラグ、来店前の確認表示
- カルテ→LINEチャットへの導線
- サロンボード予約メモ相当の手入力欄

### Phase 4：TimeTree 代替（シフト・共有カレンダー）
- スマホからのシフト希望入力（「いつも通り」「お任せ」含む）
- 管理者の作成・調整、確定シフトの確認・既読
- 共有カレンダー（出勤状況・研修・撮影・締め作業）
- 勤怠実績（早退・残業を理由付きで記録）→ 将来の社労士向け出力

### Phase 5 以降
同意書・カウンセリング電子化 → スタッフ向け掲示板 → 在庫管理（理論在庫 vs 実在庫）→ 管理者向け詳細分析 → 外部連携（Square / サロンボード）

## 5. ご相談事項への回答

| ご相談 | 回答（推奨） |
|---|---|
| KaruteKun代替の最低ライン | 「今日の来店一覧／空カルテ作成／未記入可視化／メニュー・部位・メモ／前後写真／履歴」。これで現場移行可能 |
| iPadで使いやすいカルテ | 一覧（左）→詳細（右）の2ペイン、タップ主体入力、部位はマップ/チップ選択、写真はカメラ直撮り |
| 回数券とカルテの接続 | カルテの施術行に「回数券で消化」ボタン。残回数を表示しながら1タップ消化、残高は台帳から自動算出 |
| シフトの初期実装範囲 | まず「希望入力／管理者調整／確定確認／共有カレンダー」。実績修正・社労士出力・AIは次段階 |
| LINE/サロンボード連携の順番 | ①まず手入力で運用 → ②LINE連携 → ③サロンボード（公式APIが無いため別途方式検討） |
| 既存ダッシュボードへの組み込み | 既存に足すのではなく、新基盤に統合した1アプリとして作り直し、カルテ入力を源泉に分析を自動再現 |
