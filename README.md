# Noble — ノーブル業務統合システム

エステサロン「ノーブル」（新宿店・新宿南口店・恵比寿店）の業務統合システム。
カルテ・来店記録・回数券（KaruteKun代替）、シフト・共有カレンダー（TimeTree代替）、
経営ダッシュボード、同意書・カウンセリングの電子化、掲示板、在庫管理を1つに集約しています。

## 技術スタック

- Next.js 16（App Router）+ TypeScript + Tailwind CSS v4
- Supabase（Postgres / Auth / Storage / RLS）
- デプロイ想定: Vercel（または任意の Node ホスティング）

## セットアップ手順

### 1. Supabase プロジェクトの作成

1. https://supabase.com で新規プロジェクトを作成
2. SQL Editor で `supabase/migrations/` の SQL を **番号順（001 → 030。023 は任意）**に実行
   - 各ファイル冒頭にロールバック手順を記載しています
   - 空のプロジェクトなら、`supabase/all-in-one-setup.sql` を1回実行するだけでも
     全テーブル・初期データ・オーナーアカウントが作成されます（次の 2. も含む）

### 2. 店舗とオーナーアカウントの作成

SQL Editor で `supabase/setup-production.sql` を実行すると、店舗3件と
オーナーアカウント（管理者）が作成されます。

| ロール | メール | パスワード |
|---|---|---|
| 管理者 | marin@noble.example.com | noble-marin-2026 |

メール・パスワードは SQL ファイル冒頭の変数で変更できます。
**運用開始後に必ずパスワードを変更してください。**
スタッフの追加はログイン後「経営 > マスタ管理 > スタッフ」と、
Supabase Authentication でのユーザー作成（メールを一致させる）で行います。

### 3. アプリの起動

```bash
cp .env.example .env.local   # URL と anon key を記入
pnpm install
pnpm dev                     # http://localhost:3000
```

### 4. 旧システム（カルテくん）のデータ取り込み（任意）

顧客・カルテ・回数券の履歴を CSV から取り込めます。
`supabase/migrations/023_karutekun_import.sql` を実行したうえで、
CSV を取込テーブルへ入れて `select * from public.import_karutekun();` を実行します。
手順は [`docs/DATA_IMPORT.md`](./docs/DATA_IMPORT.md) を参照してください。

### 5. 店舗別の月次目標（売上・新規件数）

目標は「経営 > 目標設定」で店舗ごと・月ごとに入力し、「経営サマリー」で実績と比較します
（年度は9月〜翌8月）。SQL でまとめて登録する場合は、SQL Editor で次の順に実行します。

1. `supabase/migrations/025_store_targets.sql`（目標テーブルと実績ビューの作成。再実行しても安全）
2. `supabase/targets-2026-09_2027-08.sql`（新宿本店・新宿南口店の 2026年9月〜2027年8月の目標）

2 は何度実行しても同じ店舗・同じ月の目標を上書きするだけで、最後に月別の目標と
年間合計（新宿本店 2,000万円/286件・新宿南口店 2,100万円/300件）が表で表示されます。

実績はビュー `store_monthly_actuals` から読み込みます。店舗ごとの「サロンワン切替月」より前の月は
Noble のデータ（売上＝実績入力の月合計、新規＝初回来店日がその月の顧客数）、切替月以降は
サロンワンのデータを使います（次の 6.）。

### 6. サロンワン連携（実績の取り込み）

サロンワンの分析API（`https://salonone.net/api/analytics/v1`）から、店舗別・月別の売上と新規来店数を
取り込みます（`GET /sales/summary?group_by=shop`。1ヶ月1リクエストで全店舗分）。

1. SQL Editor で `supabase/migrations/026_salonone_actuals.sql` を実行（再実行しても安全）。
   新宿店・新宿南口店・恵比寿店はサロンワンの店舗（新宿本店 36619・新宿南口店 36564・恵比寿店 67061）に
   対応づけられ、最後に店舗ごとの対応づけと切替月が表で表示されます
2. Vercel の環境変数に `SALONONE_API_KEY`（サロンワンの API キー）と `CRON_SECRET`（任意の長い文字列）を設定して再デプロイ。
   毎朝6時台（JST）に前月・当月分が自動で取り込まれます（`vercel.json` の `crons`）
3. 経営サマリーの「サロンワンから取り込む」で、表示中の年度（9月〜今月）をすぐ取り込めます
4. 「経営 > 目標設定」の「実績の取得元（サロンワン連携）」で、店舗ごとに **サロンワン切替月** を設定します。
   **サロンワンで会計を始めた月**を設定してください。空欄の間は Noble の実績のままです

| 経営サマリーの表示 | サロンワンの項目 |
|---|---|
| 売上（入金ベース） | `gross_sales`（粗売上：購入時点で計上） |
| 売上（会計上（消化）） | `consumed_sales`（消化売上：施術提供時点で計上） |
| 新規 | `new_visit_count`（新規の来店数。会計済みの来店のみ） |

> サロンワンで来店の会計をしていない間は、消化売上と新規来店数は 0 になり、粗売上は予約金額に近い値になります。
> 切替月は、サロンワンで会計を始めてから設定してください（目標設定の画面に、取り込んだ月の会計件数が表示されます）。
>
> API キーはサーバー側（取り込み処理）でのみ使い、ブラウザには渡しません。取り込むのは集計値だけで、
> 顧客の個人情報は取得・保存しません。取り込んだ数値（`salonone_monthly_sales`）は管理者のみ閲覧でき、
> 書き込みはサーバーの取り込み処理（service role）に限定しています。

### 7. スタッフ個人情報・書類配布・月締め/請求書・LINE定型文（027〜030）

SQL Editor で次の4ファイルを **番号順** に実行します（いずれも再実行しても安全。最後に設定結果が表で表示されます）。

1. `supabase/migrations/027_staff_private.sql` — スタッフの雇用区分（社員/アルバイト/業務委託）と、管理者のみ閲覧できる個人情報（`staff_private`）
2. `supabase/migrations/028_staff_documents.sql` — スタッフ書類（`staff_documents`）と非公開のファイル置き場 `staff-docs`（本人フォルダと管理者のみ閲覧可）
3. `supabase/migrations/029_payroll_close_invoices.sql` — 月締め（締めた月のシフト・勤務実績をロック）・送付先の設定・業務委託の請求書（金額はサーバー側で計算）
4. `supabase/migrations/030_line_messaging.sql` — LINE定型文（初期5件）・画像ライブラリ（公開のファイル置き場 `line-media`）・送信履歴

月末の流れ（管理者）は「経営 > 月締め・給与」に沿って進めます。

1. 勤務実績の確認（スタッフが「マイシフト」で記録した実績を確認。未記録は「予定どおりで一括記録」）
2. 給与・報酬の確認（時給 × 勤務時間 ＋ 交通費。時給・交通費は「シフト管理 > 時給・交通費の設定」）
3. 月締め（締めた月のシフト・勤務実績は変更不可。誤りがあれば「締めを解除」）
4. 社労士へ勤務実績CSV、税理士へ報酬・交通費CSV（「Gmailで作成」で宛先・件名・本文入りのメールが開くので、CSVを添付して送信）
5. 税理士から届いた給与明細を「スタッフ書類」で一括配布 → 各スタッフの「マイ書類」に届く
6. 業務委託スタッフは「請求書」で締めた月の請求書を作成 →「Gmailで送信」→「送信済みにする」。状況は ⑥ で確認

> 個人情報・書類はすべて RLS で保護しています（個人情報は管理者のみ、書類は本人と管理者のみ）。
> マイナンバーは保存しない運用です。LINEの送信は必ずスタッフが確認画面で内容を確かめてから送信します（自動送信はしません）。

## 動作確認手順（受け入れ条件）

1. **朝の箱作成（30秒以内）**: 今日ボード →「＋来店予定を作る」→ 顧客名の一部を入力 → 候補タップ → 時間チップ → 担当チップ →「この内容で箱を作る」
2. **未記入の即判別**: 今日ボードで左端がアンバーの行＝未記入。上部カードに未記入件数
3. **カルテ入力（1〜2分）**: 未記入行をタップ →「カルテを記入する」→ メニュー・部位をチップで選択（「前回と同じ」で複製可）→ 回数券をタップで1回消化 →「記入を完了する」
4. **回数券の整合性**: 消化→顧客ページ・`/admin/tickets` の残回数・未消化金額が即時一致。「取り消す」で復元
5. **要注意顧客**: フラグを立てた顧客を開く → フラグ＋申し送りが最上部に表示
6. **店舗切替**: ヘッダーのタブをタップ → 今日ボード・一覧・残高がすべて切替
7. **権限**: スタッフ（misaki 等）でログイン → `/admin/tickets` に直接アクセスしても `/` へリダイレクト。API レベルでも RLS と `is_admin()` で遮断
8. **レイアウト**: iPad 縦・横、スマホ（ボトムナビ）で崩れないこと
9. **店舗紹介ページ**: 未ログインのスマホで `/salons` を開く → 3店舗が並ぶ →
   「店舗の詳細・地図を見る」→ 地図・道案内・ネット予約ボタンが表示される。
   管理者は「経営 > 店舗紹介ページ」でURLをコピーできる
10. **スタッフ個人情報**: 管理者で「マスタ管理 > スタッフ」→「🔒 個人情報」に住所・最寄り駅・生年月日を登録。
    スタッフでログインすると表示されない（API でも `staff_private` は0件）
11. **書類配布**: 管理者で「スタッフ書類」→ 給与明細PDFを複数選択（ファイル名にスタッフ名）→ 自動で振り分け →「配布する」。
    スタッフの「今日」にお知らせ →「マイ書類」で開く・保存。ほかのスタッフの書類は見えない
12. **月締め**: 「月締め・給与」で ①〜③ を実行 → 締めた月はマイシフト・シフト管理で実績を変更できない。
    ④ で CSV 保存と Gmail の下書き（宛先・件名・本文入り）が開く
13. **業務委託の請求書**: 業務委託スタッフで「請求書」→ 請求者情報を登録 → 締めた月の請求書を作成 →
    「Gmailで送信」→「送信済みにする」→ 管理者の ⑥ に「送信済み」と表示
14. **LINE定型文・写真**: LINE紐付け済みの顧客ページ →「LINEで送る（定型文・写真）」→ 定型文を選ぶ（お客様名・店舗名・担当・次回予約が自動で入る）
    → 画像を選ぶ →「確認へ進む」→「この内容で送信」→ 「最近の送信」に記録される

## セキュリティ設計

- 全テーブルで RLS 有効。`staff` 行が存在する有効なログインユーザーのみアクセス可
- マスタ変更・回数券の直接修正・各種削除は管理者のみ
- 回数券の消化／取消は行ロック付きの `use_ticket` / `cancel_ticket_usage` 関数経由（二重消化防止・監査証跡）
- スタッフ別の分析データ（リピート率・販売実績）は管理者専用（RLS で読み取り自体を遮断）
- 時間給・店舗別交通費（シフトの報酬自動計算用マスタ）も管理者専用（RLS で読み取り自体を遮断）
- サロンワンの API キーはサーバー専用の環境変数。取り込んだ売上・新規数は管理者のみ閲覧可（書き込みは service role のみ）
- お客様向け公開フォーム（/f/...）は anon に RLS を開放せず、サーバー側で service role による
  トークン検証付きの読み書きのみ
- 施術写真は非公開バケット＋署名付きURL（クライアント側で圧縮してからアップロード）
